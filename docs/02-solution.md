# 02 方案设计

## 架构

```
CLI → cli.py（场景/故障注入/多轮） → agent.py（ReAct 循环 + 会话历史 + 引用校验）
        ├─ gateway.py（真实 LLM / 离线决策器，共用同一 request+trace 接口）
        └─ tools.py：search_docs / read_snippet / compare_docs / resolve_conflict
```

## 调用流程与动态决策

每轮：检索 →（失败重试一次）→ 读原文（最多两篇相关文档）→ 多篇则 compare_docs →
冲突且未确认 → 请求确认；无冲突/已确认 → 引用原文作答。工具结果触发下一步：

| 工具结果 | 下一步 |
|---|---|
| search_docs 无命中 | 有历史则结合上轮主题再检索一次，仍无 → 说明资料缺口 |
| search_docs 报错 | 重试一次；仍失败 → 说明无法确认 |
| 命中多篇高分文档 | 逐篇 read_snippet，再 compare_docs |
| compare_docs 发现冲突 | 若用户未指定适用制度 → 不裁决，列双方原文并请求确认 |
| 用户指定部门/制度 | 按指定制度引用原文作答 |
| 无关问题 | 直接说明知识库无相关资料 |

## 引用校验（防错误引用）

- quote 必须是文档正文的逐字子串（含标点）；否则记为无效引用并从列表中剔除；
- 回答中的数字必须出现在某条引用片段中，否则标为“引用不支撑回答”；
- 实质回答但无任何有效引用 → “无依据回答风险”；
- 读取多份相关文档却未 compare_docs 就给出单一结论 → 标注；
- 存在冲突记录但既未确认也未请求确认 → 标注。

## 技术取舍

- 不引入向量库：12 份文档用字二元组 + 标签命中即可覆盖改写问题，避免外部依赖；
- 冲突比较用“数字口径差异”，可解释、可测试；语义冲突由真实模型判断；
- 引用校验在系统层而非提示词层，保证任何模型都无法伪造引用。
